# Computer-Use Agents：85% 与 20.6% 之间的鸿沟

**日期：** 2026-09-28（晚）
**主题：** GUI/Computer-Use 智能体的能力天花板——OSWorld 饱和之后的真实水平
**驱动问题：** 为什么同一批模型在 OSWorld 1.0 上得分 85%（超过人类的 72%），在 OSWorld 2.0 上端到端完成率只有 20.6%？哪个数字才是"agent 能不能用电脑"的真答案？

---

## 一、两个数字，一个领域

**OSWorld 1.0（Xie et al., NeurIPS 2024，369 任务，被引 1400+）**
- 2024-04 最好成绩 ~12%；2025 年初 42%（OpenAI CUA 38.1% 起步）；2025-12 Qwen3.8-Max 达 86.1%（OSWorld-Verified 口径）
- 2026-06：Claude Fable 5 以 85% 居首，超过人类基线 ~72%；Simular Agent S3 72.6%（2025-12 自称超人类）
- 任务特征：平均 ~30 步、单应用为主、明确命名要用的 app、"不许问问题尽力做"
- **结论：基准饱和。** "它不再告诉你 agent 在哪里断掉"（Yuan, XLANG Lab）

**OSWorld 2.0（Yuan et al., arXiv 2606.29537，2026-06，68 页）**
- 108 条长程真实工作流，31 个自托管站点+专业桌面应用，69.6% 任务人类要 1 小时以上，**中位人类完成时间 1.6 小时**
- 平均轨迹 300-500 步（Opus 4.7 max-thinking 平均 318 次工具调用，1.0 是 ~30 次），最多 5 个 app 串在一个任务里
- 每任务平均 27 个打分检查点给部分分；LLM judge 权重压到 <50%（对屏幕上的视觉信息不可靠）
- **主榜：Claude Opus 4.8 二元完成率 20.6%（部分分 54.8%，500 步上限）；GPT-5.5 token 效率高得多但卡在 ~13%**
- 榜外更新：Claude Fable 5.1（发布不到 24 小时）把部分分推过 60%、二元完成率过 45%——一年内 2.0 也会被推高，但结构不变：长程完成率与步数/时长的斜率非常陡

**效率维度（MLSys 2026 oral，OSWorld-Human）**：16 个 agent 实测，最好的也要走 **2.7-4.3 倍于必要步数**。会做≠做得利索。

## 二、失败模式解剖：不是不会点按钮

OSWorld 2.0 论文最值钱的部分是失败归因。前沿 agent 不再栽在 GUI 操作或编码上，而是：

1. **丢约束**（lose track of constraints）——任务做到第 200 步忘了第 3 步说过的限制条件
2. **错过中途信息**（miss info that arrives mid-task）——Gmail 弹窗改了个数字，agent 没注意、没重规划
3. **该问不问，瞎猜**（guess rather than ask）——2.0 专门做了模拟用户供 agent 提问，绝大多数 agent 不会用
4. **跳过验证**（skip verification）——做完不检查，直接交卷
5. **隐藏状态恢复失败**（implicit state）——信息不在屏幕上，要去历史记录/前次提交里挖（报销任务里 person ID 藏在既往提交历史里）

十个挑战现象（cross-source reasoning、流式交互、动态环境、冲突信息、教程跟随、虚拟空间精度……）共同点：**全部是"工作素养"问题，不是"操作技能"问题。**

最扎心的对照实验：conflicting info 任务——选座任务截图看相邻、读 HTML 发现座位号并不相邻。agent 必须决定信哪个表征。这是 GUI 作为对抗性控制面的本质：**屏幕不是事实，是界面设计师想让你看到的投影。**

## 三、生产现实：20.6% 之外的世界（a16z, 2026-08）

- CPG 数据平台：每月 1500-2000 万次自动门户交互，agent 作为手写爬虫的**自愈 fallback**——零售商门户改版，agent 诊断断点、修复自动化，爬虫维护工程团队砍半
- 全球系统集成商：27 条工作流、每天 1500-2100 张 IT 工单，目标是重配 20-25% 人力
- 规律：**协议跟随型（protocol-following）任务跑得最好**——标准化、可重复、路径清晰（CRM 更新、保险/政务门户登录、订单处理、ServiceNow 工单）
- 最有信息量的细节：一个月跑数百万任务的运营者**不知道底下是哪个模型**——vendor 像云厂商换硬件一样换模型。模型层商品化，护城河上移到验证、升级路径、错误处理、缓存、权限、组织流程知识
- 验证悖论：agent 从合同读"net 60"读成"net 30"，记录看起来完全合理，通过一切肉眼检查，直到发票出错才发现——**背-office 工作不打部分分：每步都对，流程才算完**（85/100 意味着 15% 整单失败）
- 保险理赔提交：屏幕说"已受理"=任务完成？两天后才发现失败——**执行时没有信号能验证成功**

## 四、训练侧：RL 为什么滞后于数学/代码

- **UI-TARS-1.5/2（ByteDance）**：原生端到端 CUA 模型 + 多轮 RL + RLVR + 数据飞轮（alphaxiv 2509.02544）——业界主线：环境×数据×RL 三件套
- **GUI-G1-3B（NeurIPS 2025）**：R1-Zero 式训练，**只用 17K 开源 grounding 样本**做到 SOTA 且推理 token 更少——小模型+规则奖励的性价比路线
- **UI-R1（AAAI）**：规则奖励用于高效动作预测；**DART**：多轮 RL 的系统工程（解耦架构）——奖励细粒度化+系统效率是两个主攻方向
- 为什么滞后：GUI 奖励不像数学/代码那样干净可验证；环境重置贵（每条轨迹一个真实 VM）；动作空间连续且像素级；1.6 小时任务 × 数千 rollout = 不可承受的算力。**本质是 credit assignment 在 300 步轨迹上的方差爆炸**（与 agentic-RL 笔记的 O(T·Var[R]) 结论互相印证）
- 生态分层：前沿实验室 API（Claude/OpenAI CUA，CUA 会混入 accessibility tree/DOM） vs 开源原生 CUA（UI-TARS、Qwen 系） vs 供应商封装层（Orby、Twin、Induced）

## 五、像素 vs 语义之争（未决）

- 像素驱动（screenshots + clicks）：通用、零集成，但对布局变化脆、慢、贵
- 语义驱动（accessibility tree / DOM / API / MCP）：稳、快，但要求目标软件配合或适配层
- 现实是混合体，且**光谱正在向 agent-native 接口漂移**——但 a16z 的生产数据提醒你：世界上 90% 的遗留软件永远不会有 API，像素层是长尾的最终覆盖方式，不是过渡方案

## 核心概念（5 个）

1. **基准饱和（benchmark saturation）**：1.0 的 85% 与 2.0 的 20.6% 同时为真——测试分布决定结论分布；被解决的基准不再提供信息
2. **长程工作素养（long-horizon workmanship）**：约束追踪、主动提问、中途信息感知、终态验证——与 GUI 操作技能正交的能力簇
3. **GUI 作为对抗性控制面**：屏幕是投影不是事实；同一信息在像素层和 DOM 层可能冲突，agent 必须选择信任哪个表征
4. **RLVR 的 GUI 移植难题**：可验证奖励 × 昂贵环境重置 × 300 步 credit assignment = 方差主导的训练
5. **价值上移（模型层商品化）**：UI 导航成为 commodity，护城河在验证/升级/错误处理/组织流程知识

## 关键洞察（5 条）

1. **85% 和 20.6% 都是真相，分界线是任务的"人类耗时"维度**：OSWorld 2.0 里准确率随预估人类完成时间单调下降。短程操作技能已超人类，长程工作素养仍在实习生以下——这是两个不同的能力轴，不要混为一谈。
2. **失败模式已经从"手"上移到"脑"**：丢约束、不提问、跳过验证、错过弹窗——这些是行政素养问题。讽刺的是这些恰是最容易被 harness 层（检查清单、强制提问门、diff-based 终态断言）缓解的，说明短期工程红利在 harness 不在模型。
3. **生产部署的准入门槛不是模型分而是"可验证性"**：a16z 数据显示跑得好的全是协议跟随型任务——不是因为它简单，而是因为成功可判定。net 60/net 30 类错误过一切检查，说明**部署前先问"这个任务的'对'可机器判定吗"比"选哪个模型"重要一个数量级**。
4. **效率是被忽视的第二维度**：最好的 agent 也走 2.7-4.3 倍步数，token 成本直接乘上去。GPT-5.5 的 13% × 高 token 效率 vs Opus 的 20.6% × 高 token 消耗——生产里这条 trade-off 曲线每天都在被重新算。
5. **模拟用户是基准设计的关键创新**：从 1.0 的"不许问"到 2.0 的"可以问模拟用户"，把"知道什么时候该问"第一次变成了可测量的能力——这是任务-环境-交互三者同时进化的范本。

## Next Actions（可落地）

1. **本周**：把自己手头一个 agent 任务的"成功断言"写成机器可判定的终态检查（哪怕只是一个 diff 命令）——这是从 20.6% 到生产的唯一桥梁
2. **给长程 agent 加三个 harness 件**：约束清单注入（每 N 步重播任务约束）、提问门（关键分叉强制 ask-user）、终态验证步（提交前强制 self-check）——对应 OSWorld 2.0 前四大失败模式
3. **跟 UI-TARS-2 / GUI-G1 系开源 CUA 模型**：17K 样本 R1-Zero 路线说明 grounding 数据的质量-数量 trade-off 远未定型，小团队有窗口
4. **评估自家用例时抄 OSWorld 2.0 的三招**：自托管环境（可重置）、多检查点部分分（可诊断）、模拟用户（可测提问能力）——这三招比任何单一模型分数都更能预测生产表现
