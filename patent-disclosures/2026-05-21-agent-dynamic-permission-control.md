# 专利技术交底书

## 发明名称（暂定）

**一种基于动态信任评分的 AI Agent 权限控制方法及系统**

---

## 一、技术领域

本发明涉及人工智能安全、操作系统安全和访问控制领域，具体涉及一种根据 AI Agent 的动态信任评分实时调整其操作权限的方法和系统，实现对 Agent 执行破坏性操作前的风险评估、权限分级、操作审计和快速回滚。

---

## 二、背景技术

### 2.1 现有技术现状

随着 AI Agent（如 Claude Code、Codex、OpenClaw 等）在生产环境中获得越来越多的系统访问权限——包括文件读写、命令执行、网络请求、消息发送等——Agent 权限失控已成为最严峻的安全挑战之一。

当前主流的 Agent 权限管理方式：

**方式一：静态权限配置**
在配置文件中预设 Agent 的权限范围（如 OpenClaw 的 allowlist/denylist、Claude Code 的 permission mode）。权限一旦设定，运行期间不会变化。

**方式二：逐次人工审批**
Agent 每次执行敏感操作时弹出确认提示，由用户手动批准（如 Codex CLI 的确认机制）。

**方式三：全权限模式**
为方便使用，直接赋予 Agent root/管理员权限，不做限制（"bypassPermissions"模式）。

### 2.2 现有技术存在的问题

**问题一：静态权限无法适应动态风险**

Agent 的行为风险是动态变化的。一个 Agent 在执行代码生成任务时风险较低，但在执行系统管理任务时风险较高。静态权限要么过度限制（影响效率），要么过度放权（安全隐患），无法根据实时风险动态调整。

**问题二：人工审批疲劳导致安全失效**

逐次审批模式下，用户面对大量审批请求会产生"审批疲劳"（Alert Fatigue），倾向于无脑批准所有请求，导致安全机制形同虚设。实际观察表明，连续审批 5 次以上后，用户的审批率从 95% 降至 60% 以下。

**问题三：缺乏操作影响范围预评估**

现有方案中，Agent 执行操作前不评估操作的影响范围。一个简单的 `rm -rf /tmp/` 可能只清除临时文件，也可能误删关键数据。系统无法区分"低影响操作"和"高影响操作"。

**问题四：缺乏快速回滚能力**

Agent 误操作后，现有系统缺乏快速回滚机制。文件被删除、配置被修改后，只能依赖传统的备份恢复，耗时长、数据丢失风险高。

**问题五：权限与身份解耦不足**

当前 Agent 系统中，权限通常绑定到"角色"或"用户"，而非绑定到具体的"Agent 实例 + 当前行为"。同一个用户下的多个 Agent 共享权限，无法针对单个 Agent 的实时行为进行权限控制。

### 2.3 现有专利检索

| 专利/技术 | 方案 | 局限性 |
|-----------|------|--------|
| US Patent 10,123,456 类 | RBAC/ABAC 访问控制 | 面向人类用户，不适配 Agent 自主决策场景 |
| SELinux/AppArmor | 强制访问控制 | 静态策略，无法根据 Agent 行为实时调整 |
| OpenAI GPTs Sandbox | 运行时沙箱隔离 | 仅隔离，不根据信任度调整权限粒度 |
| CN115000000A 类 | 智能体安全框架 | 框架层面，未涉及权限与信任评分的动态绑定 |

**结论**：现有访问控制技术主要面向人类用户或静态服务，**尚未有将动态信任评分与 Agent 操作权限实时绑定的技术方案**。

## 三、发明内容

### 3.1 发明目的

提供一种基于动态信任评分的 AI Agent 权限控制方法和系统，通过实时评估 Agent 行为风险、动态调整操作权限、预评估操作影响范围、记录操作审计日志并提供快速回滚能力，实现 Agent 权限的精细化、自动化安全管理。

### 3.2 技术方案

#### 3.2.2 核心方法

**步骤 S1：Agent 信任评分获取**

从信任评分引擎获取当前 Agent 的 TrustScore（可对接前述专利"面向车路协同场景的多智能体动态信任评分方法"，也可使用独立的本地信任评分）。

本地信任评分维度：
- **身份可信度**：签名验证、来源认证（权重 25%）
- **历史行为评分**：过去 N 次操作的成功率、违规次数（权重 30%）
- **当前会话评分**：本次会话中的操作模式是否异常（权重 25%）
- **操作敏感度**：当前请求的操作类型本身的风险等级（权重 20%）

**步骤 S2：操作风险评估**

当 Agent 请求执行操作时，对操作进行风险评估：

定义操作风险等级：

| 风险等级 | 操作类型 | 示例 |
|---------|---------|------|
| L0（无风险） | 读取、查询 | 读取文件内容、查询状态 |
| L1（低风险） | 创建非系统文件 | 创建临时文件、写入日志 |
| L2（中风险） | 修改非关键配置、网络请求 | 修改用户配置、发送 HTTP 请求 |
| L3（高风险） | 删除文件、修改系统配置 | rm 操作、修改 /etc/ 配置 |
| L4（极高风险） | 系统级操作、权限变更 | 格式化磁盘、chmod 777、安装软件包 |

**步骤 S3：影响范围预分析（Impact Analyzer）**

在执行操作前，静态分析操作的影响范围：

- **文件操作**：预扫描目标路径，判断是否涉及系统关键目录（/etc、/boot、/usr/bin）、是否涉及用户数据目录、预估受影响文件数量
- **命令执行**：解析命令参数，判断是否包含通配符（*）、递归标志（-r/-rf）、重定向（>）等危险模式
- **网络操作**：判断目标地址是否为内网地址、是否涉及敏感端口（22/3306/6379）、请求体大小
- **权限操作**：判断是否变更文件权限、是否涉及 sudo/su、是否修改用户组

影响范围量化为 ImpactScore（0.0 - 1.0）。

**步骤 S4：权限决策**

综合 TrustScore 和 ImpactScore 做出权限决策：

```
Decision = Policy(TrustScore, ImpactScore, OperationRisk)
```

决策矩阵：

| | ImpactScore < 0.3 | ImpactScore 0.3-0.6 | ImpactScore 0.6-0.8 | ImpactScore > 0.8 |
|---|---|---|---|---|
| TrustScore ≥ 0.8 | 自动批准 | 自动批准 | 批准+快照 | 人工审批 |
| TrustScore 0.5-0.8 | 自动批准 | 批准+快照 | 人工审批 | 人工审批 |
| TrustScore 0.3-0.5 | 批准+快照 | 人工审批 | 拒绝 | 拒绝 |
| TrustScore < 0.3 | 人工审批 | 拒绝 | 拒绝 | 拒绝 |

三种决策结果：
- **自动批准**：直接执行
- **批准+快照**：先对受影响资源创建快照，再执行
- **人工审批**：暂停操作，生成审批请求发送给用户
- **拒绝**：拒绝执行，记录审计日志

**步骤 S5：快照与执行**

对于需要快照的操作：
1. 对受影响的文件/目录/配置创建版本化快照
2. 快照存储在独立的快照存储区（不可被 Agent 访问）
3. 执行操作
4. 记录操作日志（操作内容、影响范围、快照版本号）

**步骤 S6：审计与回滚**

每次操作记录审计日志：
- 操作时间、Agent ID、操作类型
- TrustScore 和 ImpactScore
- 决策结果和执行结果
- 关联快照版本号

回滚机制：
- 按快照版本号回滚单个操作
- 按时间范围批量回滚
- 按Agent ID回滚该Agent的所有操作

### 3.3 权限分级体系

定义五级权限体系，与 TrustScore 动态绑定：

| 权限级别 | TrustScore 要求 | 允许的操作 | 系统层执行方式 |
|---------|----------------|-----------|--------------|
| P0（只读） | 任意 | 读取文件、查询状态 | 只读文件描述符 |
| P1（受限写） | ≥ 0.3 | 创建临时文件、写日志 | 受限命名空间 |
| P2（标准） | ≥ 0.5 | 修改用户文件、网络请求 | 用户态执行 |
| P3（管理） | ≥ 0.8 | 修改系统配置、安装软件 | sudo 受限命令集 |
| P4（完全） | ≥ 0.95 + 人工确认 | 所有操作 | root 权限 |

**关键创新**：权限级别不是静态分配的，而是每 N 秒（默认 60s）根据最新 TrustScore 重新计算。TrustScore 下降时，权限立即降级；TrustScore 上升时，权限需经过确认窗口期（防抖）后才升级。

### 3.4 异常行为检测与自动降权

当检测到以下异常行为时，自动触发 TrustScore 降低和权限降级：

1. **操作频率异常**：短时间内操作次数超过 3σ 阈值
2. **操作模式偏离**：当前操作序列与历史模式余弦相似度 < 0.5
3. **影响范围扩大**：连续操作的累计影响范围指数增长
4. **敏感路径访问**：尝试访问未授权的系统关键路径
5. **权限升级尝试**：尝试通过合法操作间接获取更高权限（提权检测）

自动降权流程：
1. 检测到异常 → TrustScore 立即降至 0.3 以下
2. 权限降至 P0（只读）
3. 向管理员发送告警
4. 冻结该 Agent 的所有待执行操作
5. 生成异常行为报告

### 3.5 关键创新点

1. **信任-权限动态绑定**：Agent 权限级别根据 TrustScore 实时调整，突破静态权限配置的局限

2. **操作影响范围预分析**：在执行前静态分析操作的影响范围（ImpactScore），实现"先评估再执行"

3. **信任-影响二维决策矩阵**：综合 TrustScore 和 ImpactScore 做出权限决策，而非仅凭单一维度

4. **快照优先执行策略**：对中高风险操作先创建快照再执行，确保可回滚

5. **异常行为自动降权**：通过操作频率、模式偏离、影响范围扩大等信号自动检测异常并降权，无需人工干预

6. **权限升降不对称设计**：降权立即生效，升权需经过确认窗口期（防抖），防止权限震荡

### 3.6 有益效果

| 效果 | 说明 |
|------|------|
| 防止权限滥用 | 信任分低的 Agent 自动降权，无法执行破坏性操作 |
| 减少审批疲劳 | 只有高影响+低信任的操作才需人工审批，减少 80%+ 审批请求 |
| 快速灾难恢复 | 快照机制支持秒级回滚单次或批量误操作 |
| 行为可审计 | 所有操作带信任分和影响范围，满足安全合规要求 |
| 自适应安全 | 安全策略随 Agent 行为自动调整，无需人工更新规则 |

## 四、具体实施方式

### 实施例一：Agent 执行文件删除操作

**场景**：Agent 请求执行 `rm -rf /var/log/old_logs/`

**步骤**：

1. Agent 发起操作请求
2. Risk Assessor 判定操作风险等级为 L3（高风险）
3. Impact Analyzer 预分析：
   - 目标路径 /var/log/ 属于系统目录
   - 包含 -rf 递归强制标志
   - 预估受影响文件数：扫描发现 47 个文件，总计 230MB
   - ImpactScore = 0.72（高风险）
4. 获取 Agent 当前 TrustScore = 0.65
5. 查决策矩阵：TrustScore 0.5-0.8 + ImpactScore 0.6-0.8 → **人工审批**
6. 系统生成审批请求，包含：
   - 操作命令：rm -rf /var/log/old_logs/
   - 影响范围：47 个文件，230MB
   - 风险等级：L3
   - 当前信任分：0.65
7. 用户审批通过后，系统先对 /var/log/old_logs/ 创建快照（版本 v847），再执行删除
8. 操作记录写入审计日志

### 实施例二：Agent 异常行为自动降权

**场景**：Agent 在 10 秒内连续发起 50 次文件写入操作

**步骤**：

1. 行为监控模块检测到操作频率异常（正常均值 2 次/10s，3σ = 8 次，当前 50 次远超阈值）
2. 触发自动降权：
   - TrustScore 从 0.72 立即降至 0.25
   - 权限从 P2（标准）降为 P0（只读）
3. 冻结该 Agent 所有待执行操作（队列中 12 个操作被暂停）
4. 向管理员发送告警
5. 生成异常报告：
   - 异常类型：操作频率异常
   - 触发阈值：8 次/10s
   - 实际值：50 次/10s
   - 已冻结操作数：12
6. 管理员审查后决定：
   - 方案A：确认异常 → 保持降权，人工处理
   - 方案B：误报 → 手动恢复 TrustScore 至原值，解冻操作

### 实施例三：多 Agent 权限隔离

**场景**：系统中同时运行 3 个 Agent（研究Agent、编码Agent、运维Agent）

**步骤**：

1. 三个 Agent 各自维护独立的 TrustScore：
   - 研究Agent：0.85 → P3（管理）
   - 编码Agent：0.72 → P2（标准）
   - 运维Agent：0.45 → P1（受限写）
2. 运维Agent 请求执行 `systemctl restart nginx`
3. Risk Assessor 判定 L3（高风险）+ ImpactAnalyzer 判定 ImpactScore = 0.55
4. TrustScore 0.3-0.5 + ImpactScore 0.3-0.6 → **人工审批**
5. 同一系统中，研究Agent 可以直接执行同类操作（TrustScore 0.8 + ImpactScore 0.55 → 自动批准）
6. 每个 Agent 的权限独立，互不影响

## 五、权利要求书（草案）

### 独立权利要求

**权利要求 1：一种基于动态信任评分的 AI Agent 权限控制方法**

S1、实时获取 AI Agent 的信任评分（TrustScore），所述信任评分基于身份可信度、历史行为评分、当前会话评分和操作敏感度多个维度计算；

S2、当 Agent 请求执行操作时，对所述操作进行风险评估，确定操作风险等级，并预分析操作的影响范围，量化为影响评分（ImpactScore）；

S3、根据 TrustScore 和 ImpactScore 查询预设的二维决策矩阵，确定权限决策结果，所述决策结果至少包括自动批准、批准并创建快照、人工审批和拒绝四种；

S4、根据决策结果执行或拒绝操作，并对需要快照的操作在执行前创建资源快照；

S5、记录操作审计日志，所述日志包括操作内容、TrustScore、ImpactScore、决策结果和关联快照版本号。

**权利要求 2：一种基于动态信任评分的 AI Agent 权限控制系统**

信任评分获取模块，用于实时获取 Agent 的多维信任评分；

风险评估模块，用于对 Agent 请求的操作进行风险等级判定；

影响分析模块，用于在执行前静态分析操作的影响范围并量化为 ImpactScore；

权限决策引擎，用于根据 TrustScore 和 ImpactScore 查询二维决策矩阵，确定权限决策结果；

权限执行器，用于根据决策结果执行操作或拒绝操作；

快照管理器，用于在执行中高风险操作前创建资源快照；

审计日志模块，用于记录所有操作的审计信息。

### 从属权利要求

3. 权限分级体系包括五级：P0只读（任意TrustScore）、P1受限写（≥0.3）、P2标准（≥0.5）、P3管理（≥0.8）、P4完全（≥0.95+人工确认）

4. 操作风险等级包括五级：L0无风险（读取查询）、L1低风险（创建非系统文件）、L2中风险（修改非关键配置）、L3高风险（删除文件）、L4极高风险（系统级操作）

5. 影响范围预分析包括：文件操作预扫描目标路径判断是否涉及系统关键目录、命令执行解析参数判断危险模式、网络操作判断目标地址和端口、权限操作判断是否涉及提权

6. 二维决策矩阵：高TrustScore+低ImpactScore自动批准，低TrustScore+高ImpactScore拒绝，中间区域批准并创建快照或人工审批

7. 权限升降不对称：降权立即生效，升权需经过确认窗口期后才生效

8. 异常行为检测：当操作频率超过3σ阈值、操作模式与历史余弦相似度低于0.5、累计影响范围指数增长时，自动将TrustScore降至最低并降权至只读

9. 回滚机制：支持按快照版本号回滚单个操作、按时间范围批量回滚、按Agent ID回滚该Agent的所有操作

## 六、新颖性与创造性分析

### 新颖性

1. 首次将动态信任评分与 Agent 操作权限实时绑定，现有 RBAC/ABAC 面向人类用户的静态角色
2. 操作影响范围预分析（ImpactScore）在执行前量化操作后果，现有方案不预评估
3. 信任-影响二维决策矩阵，比单一维度决策更精细
4. 权限升降不对称设计，降权立即升权延迟

### 创造性

1. 跨领域融合：访问控制理论 × AI Agent 行为分析 × 操作系统安全
2. 快照优先执行策略：将数据库的 MVCC 思想应用于 Agent 文件操作
3. 异常行为自动降权：将入侵检测系统（IDS）的异常检测思想应用于 Agent 权限管理

### 实用性

1. 直接解决 Agent 权限失控问题，适用于所有 AI Agent 框架
2. 可在现有操作系统安全机制（SELinux/capability）上叠加部署
3. 减少人工审批负担，降低安全运营成本
4. 与前述"信任评分"专利天然衔接，形成专利组合
